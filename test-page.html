Password Field Test Harness

Each section below simulates a different real-world case where password fields get hidden. Reload the extension and this page, then test the 👁 icon on every one.

1. Plain vanilla input (no framework)

The simplest case — a static HTML password field with no JS behind it.

2. Framework-style "controlled input" (simulates React/Swagger UI)

This field is re-rendered by a timer every 500ms, exactly like a React component re-asserting its own state. This is the case that broke the v1 toggle-based approach — the field's type attribute gets forced back to "password" repeatedly.

3. Value set programmatically, no keystrokes fired

Simulates an API client or password manager filling the field via JS without triggering a normal "input" event — the reason the extension polls the value instead of relying only on keystroke events.

4. Field inside Shadow DOM

Some component libraries (web components, some design systems) render inputs inside a shadow root, which a plain querySelectorAll cannot see into. This is a known limitation — see note below.
